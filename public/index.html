📖 How to Use ZeroHost & AI Architecture Blueprint

⚡ The Zero-Cost Dual-Repository Pipeline

Traditional hosts like Vercel and Netlify charge exorbitant bandwidth bills ($20–$50/100GB) when users download heavy software or traffic spikes. ZeroHost solves this permanently using an automated Dual-Repository Architecture:

Step 01 🔒 PRIVATE
📥 Source Ingestion
You edit files in the File Manager or push via Git CLI into your strictly private repository (<slug>-source). Your readable code, private commits, and secrets stay 100% hidden.
Step 02 ⚙️ ACTIONS
🤖 Automated Build
GitHub Actions runs inside an isolated runner: validates relative paths, compresses stylesheets, strips private references, and prepares production artifacts.
Step 03 🌍 PUBLIC
📡 Gateway Sync
Only the production-ready src/ files and assets/ are synchronized to your public gateway (<slug>-cdn). The private repo is never exposed to the public.
Step 04 🚀 GLOBAL CDN
🌐 Multi-Edge Delivery
src/index.html is served instantly via GitHub Pages Edge with automatic SSL, while heavy media and installers stream globally via jsDelivr CDN at multi-gigabit speeds.
💡 Total Hosting Bill: $0.00 / month forever. Bandwidth is unlimited via Cloudflare/Fastly backed multi-CDN nodes.

📂 Folder Separation: Run Files vs Storage Assets

To keep your site fast and avoid hosting traps, ZeroHost strictly divides files into two folders:

ZeroHost Project Structure: ├── src/ <-- ⚡ RUN FILES (Web Code) │ ├── index.html (ONLY public entry point - serves as homepage) │ ├── css/style.css (Frontend styles, dark mode, responsive layout) │ └── js/main.js (Client-side interactive scripts) └── assets/ <-- 📦 STORAGE ASSETS (Heavy Media & Downloads) ├── logo.png (Brand graphics and screenshots) ├── banner.webp (High-res hero visuals) ├── App_Installer.exe (Desktop installer streamed via jsDelivr CDN) └── Extension.zip (Browser add-ons and binary archives)

You are an expert front-end web developer building a modern, high-performance website for the ZeroHost platform.

STRICT PLATFORM CONSTRAINTS & ARCHITECTURE:
1. DIRECTORY STRUCTURE:
   - src/index.html: The SINGLE public entry file and homepage.
   - src/css/style.css: All custom styles, themes, responsive CSS, and animations.
   - src/js/main.js: All client-side JavaScript, DOM interactivity, and dynamic behaviors.
   - assets/: Storage directory for all images, icons, illustrations, video media, and downloadable binary files (e.g., .exe, .zip, .pdf).

2. RELATIVE PATH CONVENTION (CRITICAL):
   - GitHub Pages and ZeroHost CDN serve sites on a repository subpath (e.g. https://<user>.github.io/<repo>/).
   - NEVER use leading slashes (e.g. DO NOT use "/css/style.css" or "/assets/logo.png" or "/index.html").
   - ALWAYS use clean relative paths:
     * Stylesheet: <link rel="stylesheet" href="css/style.css">
     * JavaScript: <script src="js/main.js" defer></script>
     * Images: <img src="assets/hero.png" alt="Hero">
     * Downloads: <a href="assets/app-installer.exe" download>Download</a>

3. ASSET SEPARATION & PRIVACY:
   - Heavy media and downloadable files must be referenced from "assets/".
   - NEVER hardcode private repository URLs (like *-source) or personal GitHub tokens in HTML/JS.

4. DESIGN & PERFORMANCE:
   - Modern, aesthetic UI with dark-mode elegance, glassmorphism, responsive mobile layout, and zero dependencies.
